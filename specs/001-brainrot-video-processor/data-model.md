## Entity: UserIdentity

**Storage**: Azure Table Storage — `PoMemeVideo` RG  
**Table**: `UserIdentities`  
**Partition Key**: `IdentityType` (`Microsoft` | `ANON`)  
**Row Key**: `IdentityId` (GUID)

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| IdentityId | Guid | PK (RowKey) | Generated on first login |
| IdentityType | enum | `Microsoft` \| `ANON` | |
| DisplayName | string | max 100 | Email for Microsoft; `ANONxxxxxxx` for ANON |
| CreatedAt | DateTimeOffset | UTC | |

**Validation rules**:
- `DisplayName` for ANON must match pattern `^ANON\d{6}$`.
- `DisplayName` for Microsoft must be a valid email address.

**State transitions**: Identity is created once on first login; never updated.

## Entity: VideoSession

**Storage**: Azure Table Storage — `PoMemeVideo` RG  
**Table**: `VideoSessions`  
**Partition Key**: `UserId`  
**Row Key**: `SessionId` (GUID)

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| SessionId | Guid | PK (RowKey) | |
| UserId | Guid | FK → UserIdentity | PartitionKey |
| SourceBlobPath | string | max 512 | e.g. `sessions/{sessionId}/source.mp4` |
| VideoDurationSeconds | double | > 0 | Extracted client-side after upload |
| AggressiveVisuals | bool | | Set at ingestion |
| Status | enum | `Ingesting\|Processing\|Complete\|Error` | |
| ErrorMessage | string? | nullable | Populated only on `Error` status |
| CreatedAt | DateTimeOffset | UTC | |
| CompletedAt | DateTimeOffset? | UTC, nullable | Set when `Complete` or `Error` |
| OutputBlobPath | string? | nullable | e.g. `sessions/{sessionId}/output.mp4` |

**State machine**:
```
[Created] → Ingesting → Processing → Complete
                                  └→ Error
```
- `Ingesting`: SAS upload in progress.
- `Processing`: Engine running (AI Vision → Gemma 4 → token-bucket → render queue).
- `Complete`: `OutputBlobPath` populated; download available.
- `Error`: `ErrorMessage` populated; user can Wipe Buffer and retry.

## Entity: Keyframe

**Storage**: Azure Blob Storage — `PoMemeVideo` RG  
**Container**: `keyframes`  
**Blob path**: `sessions/{sessionId}/frames/{sequenceNumber}.png` (1-bit green-scale PNG)

> **Note**: Keyframes are ephemeral client-side artefacts. The dithered PNG is generated by the browser canvas and optionally stored to Blob for diagnostics only; the primary consumer is the `DitheredKeyframeStrip` Blazor component which holds the data URL in memory. No Table Storage record is required for Keyframe.

| Field | Type | Notes |
|-------|------|-------|
| SessionId | Guid | |
| SequenceNumber | int | 0-based; frame at t = SequenceNumber × 3 seconds |
| TimestampOffsetSeconds | double | = SequenceNumber × 3.0 |
| DataUrl | string | `data:image/png;base64,...` (client memory only) |

## Entity: DirectorScript

**Storage**: Azure Table Storage — `PoMemeVideo` RG  
**Table**: `DirectorScripts`  
**Partition Key**: `SessionId`  
**Row Key**: `"script"` (single record per session)

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| SessionId | Guid | PK (PartitionKey) | |
| GeneratedAt | DateTimeOffset | UTC | |
| TotalSoundCount | int | ≥ 0 | |
| AverageDensitySeconds | double | | = VideoDuration / TotalSoundCount |
| EntriesJson | string | JSON array | Serialised `ScriptEntry[]`; stored as single cell |

> `ScriptEntry` items stored inline as JSON in `EntriesJson` given the bounded size (max ~72 entries for a 60s video at 2s minimum gap, much fewer in practice).

## Entity: ScriptEntry

**Storage**: Embedded within `DirectorScript.EntriesJson` (no separate table)

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| EntryId | Guid | | |
| SessionId | Guid | | |
| TimestampMs | long | ≥ 0; < (duration × 1000) | Must respect 2 s minimum gap |
| SoundId | Guid | FK → SoundAsset | |
| ActionVectorTags | string[] | min 1 | e.g. `["fail", "thud"]` |
| SelectionRationale | string | max 500 | Human-readable reason from Gemma 4 |
| IsIronic | bool | | True when pairing is intentionally incongruous |
| VisualEffect | enum? | nullable | `DeepFry\|SnapZoom\|MotionBlur\|Overlay\|None` |
| EffectIntensity | double? | 0.0–1.0, nullable | Normalised intensity; null when no effect |
| OverlayAssetId | string? | nullable | e.g. `"wasted"`, `"question-marks"` |
| PlacementType | enum | `Triggered\|Fallback\|Conflict-Winner` | Token-bucket audit trail |

**Validation rules**:
- No two `ScriptEntry` items in the same `DirectorScript` may have `TimestampMs` values within 2,000 ms of each other.
- `VisualEffect` must be non-null when the parent `VideoSession.AggressiveVisuals` is `true`.
- `OverlayAssetId` must be non-null when `VisualEffect == Overlay`.

## Entity: SoundAsset

**Storage**:  
- Catalogue metadata → Azure Table Storage `SoundAssets` table (PoMemeVideo RG)  
- Audio file → Azure Blob Storage `sounds` container (PoMemeVideo RG)

**Table partition strategy**: `PartitionKey = "library"`, `RowKey = SoundId`

| Field | Type | Constraints | Notes |
|-------|------|-------------|-------|
| SoundId | Guid | RowKey | |
| DisplayName | string | max 100 | e.g. `"Vine Boom"` |
| DurationMs | int | > 0 | |
| ActionVectorTags | string[] | min 1 | e.g. `["boom", "impact", "fail"]` |
| BlobUrl | string | valid HTTPS URL | Points to Blob Storage audio file |
| EmbeddingVector | float[] | 64 dimensions | Normalised; loaded into memory cache at startup |

**Cache strategy**: All `SoundAsset` records loaded into `IMemoryCache` at startup via `ISoundAssetRepository.LoadAllAsync()`. Cache is refreshed on a 24-hour sliding window. SIMD cosine similarity (`TensorPrimitives.CosineSimilarity`) runs in-process against the cached vectors.

## Azure Storage Layout

```
Azure Table Storage (PoMemeVideo RG)
├── UserIdentities          (PartitionKey: IdentityType | RowKey: IdentityId)
├── VideoSessions           (PartitionKey: UserId | RowKey: SessionId)
├── DirectorScripts         (PartitionKey: SessionId | RowKey: "script")
└── SoundAssets             (PartitionKey: "library" | RowKey: SoundId)

Azure Blob Storage (PoMemeVideo RG)
├── videos/
│   └── sessions/{sessionId}/
│       ├── source.{ext}          # Original upload (SAS write by client)
│       └── output.mp4            # Rendered meme video
├── sounds/
│   └── {soundId}.{mp3|wav}       # Meme sound assets
└── keyframes/                    # Optional diagnostic store (client-generated frames)
    └── sessions/{sessionId}/
        └── {sequenceNumber}.png
```

## Key Design Decisions

1. **EntriesJson denormalisation**: `ScriptEntry` items stored as a JSON blob inside `DirectorScript` rather than as individual Table rows. Rationale: all entries are always read together (no partial reads needed); Table Storage charges per operation, so one read per session is optimal. Max payload is ~50 KB for a 60-second video — well within Azure Table Storage's 1 MB entity limit.

2. **No Keyframe table entity**: Keyframes are browser-generated and consumed immediately in the UI. Storing them server-side would require an upload per frame (≥20 round-trips for a 60-second video). Only stored to Blob optionally for diagnostics behind a feature flag.

3. **SoundAsset in-memory cache**: The 200+ asset catalogue is static at runtime. In-memory SIMD matching at microsecond speed is preferable to a Table Storage query per sound per trigger event.
