Tier 1 · The thirty-second read

What this is, in one table

PoMemeVideo is one ASP.NET Core host (PoMemeVideo.Api) that serves a Blazor WebAssembly client from its own origin, stores everything in Azure Table & Blob Storage, calls one Azure AI Foundry deployment to write a “director’s script”, and shells out to a bundled static FFmpeg to render the result.

How the app works, in the words of its own code

A run begins on the Source page. The browser asks for a write-scoped SAS URI, uploads the video straight to Blob Storage, then confirms the session. That direct-upload path is the reason the only CORS configuration in the system exists at all: “Browser direct-upload (a SAS PUT straight to Blob Storage) only works if the storage account has a CORS rule listing the page’s origin. This MUST run in EVERY environment” EndpointMappingExtensions.cs:230-234. The client then extracts keyframes in-page and posts them as base64 PNGs; the server stores each frame, runs vision analysis immediately and persists the labels as a JSON blob “so the engine can read them without re-calling the AI” IngestionEndpoints.cs:154.

Pressing initiate queues the session on an in-process channel. The engine loads the pre-computed labels, ranks the sound library against each one, and applies a token bucket whose job is stated plainly: “Within the same 2-second window, the request with the highest cosine score wins. Gaps exceeding MaxGapMs receive a fallback placement” TokenBucketTimingService.cs:23-25. The approved cues and a capped 48-sound menu go to the AI director, which returns an enriched script — rationale, ironic-pairing flag, visual effects, captions. Every failure along that path degrades rather than aborts: a director timeout logs “Director call timed out; continuing with deterministic fallback entries” and the engine builds basic placements itself RunEngineCommand.cs:303-310,325-345.

The script is persisted to Table Storage, streamed cue-by-cue to the browser over SignalR, and handed to the render pipeline. FFmpeg downloads the source, muxes the meme audio, burns captions and overlays, uploads the MP4 and flips the session to Complete. The hub that carries all of this is deliberately anonymous, and the comment says why: “The hub carries no user-scoped data — it only relays progress into groups keyed by sessionId… under the deny-by-default FallbackPolicy a negotiate without the auth cookie would 401 and the client would silently lose all live progress updates” EndpointMappingExtensions.cs:169-173.

Tier 3 · Schemas, bindings and keys

The detail behind the summary

Strongly-typed identifiers

Four readonly record struct ids exist because “repo.GetByIdAsync(userId, sessionId) — arguments transposed — previously compiled and silently returned null” StronglyTypedIds.cs:1-5. The invariant that made them safe to introduce over live data is that each is wire- and storage-identical to a bare Guid.

[JsonConverter(typeof(SessionIdJsonConverter))]
public readonly record struct SessionId(Guid Value) : IParsable<SessionId>
{
    public override string ToString() => Value.ToString();
    public static SessionId Parse(string s, IFormatProvider? provider) => new(Guid.Parse(s));
}

public sealed class SessionIdJsonConverter : JsonConverter<SessionId>
{
    public override SessionId Read(ref Utf8JsonReader reader, Type _, JsonSerializerOptions __)
        => new(reader.GetGuid());
    public override void Write(Utf8JsonWriter writer, SessionId value, JsonSerializerOptions _)
        => writer.WriteStringValue(value.Value);
}

StronglyTypedIds.cs:15-31,92-99

The convention is strong types inside, primitives at the edges: domain entities, repository and service contracts take SessionId/UserId/SoundId/EntryId; the wire DTOs in Shared/Models keep raw Guid VideoSessionDto.cs:7-8. Minimal-API route parameters bind the strong type directly through IParsable<T> IngestionEndpoints.cs:108-109.

Tier 1 · Register

Gaps and risks found while documenting

Each entry was found by reading the code for this document set, and each is anchored to the line that proves it. Nothing here is speculative; where a claim was checked against the running application, the observed response is quoted.

Registered but unused

The AI resilience pipeline is registered and never resolvedHigh

AddHttpClient("AiFoundry") attaches CorrelationPropagationHandler and AddStandardResilienceHandler() — retry, timeout and circuit breaker — to a named client ServiceRegistrationExtensions.cs:93-95. CreateClient("AiFoundry") appears nowhere in the solution. Both AI services construct AzureOpenAIClient directly AiFoundryDirectorService.cs:49-51AiFoundryVisionService.cs:58-60, so neither the resilience pipeline nor correlation-header propagation applies to a single AI call. The comment above the registration — “per the .NET 10 resilience mandate” — and AGENT.md §9’s claim that correlation ids are “forwarded on outbound HTTP (AI Foundry, Azure OpenAI)” both describe behaviour that does not occur.

The meme-persona selector never reaches the modelMedium

DirectorPrompt.Build accepts a memePersona argument and maps five personas onto prompt text DirectorPrompt.cs:49,59-67. The only caller omits it: DirectorPrompt.Build(labelsJson, soundsCompact, hasRealVisionData) AiFoundryDirectorService.cs:78. The value is chosen in the UI Source.razor:141, sent, persisted to the MemePersona column VideoSessionTableRepository.cs:104 and displayed back on the History page Results.razor:98 — but every session is directed with the default persona.

Four shared-platform helpers are dead in this appLow

PoPlatform.SessionCookieName, AntiforgeryCookieName, TagEndUser and ApplicationProperty are declared PoPlatform.cs:34,78,82,125 and referenced nowhere outside the file. The Serilog enricher hard-codes the literal "Application" rather than using the constant that exists to keep that spelling uniform StartupConfigurationExtensions.cs:99. The __Host- cookie-prefix helper in particular is unused, so the auth cookie does not carry that browser-enforced protection.

DirectorPrompt.SerializeSounds and AiFoundry:DefaultDeploymentLow

The non-compact sound serialiser is public and has no caller DirectorPrompt.cs:18 — only SerializeSoundsCompact is used. Its doc-comment is also duplicated verbatim DirectorPrompt.cs:10-17. AiFoundry:DefaultDeployment is set in both appsettings files appsettings.json:28appsettings.Development.json:16 and read by nothing; the actual default lives in code RuntimeAiSettings.cs:17.

Declared but never emitted

No endpoint emits RFC 9457 — including the ones that advertise itMedium

AddProblemDetails() is registered ServiceRegistrationExtensions.cs:28 and PUT /api/config/ai-model is annotated .ProducesProblem(400) ConfigEndpoints.cs:76, but the handler returns Results.BadRequest(string) and the wire carries a bare JSON string ConfigEndpoints.cs:60,66. GlobalExceptionHandler writes an anonymous object with RFC 7231 type URIs and two non-standard members GlobalExceptionHandler.cs:40-71. Its own summary claims RFC 7807 GlobalExceptionHandler.cs:8.

Sign-in telemetry cannot fire in the default configurationLow

SignInTelemetry.TrackFrom is wired only inside the hasAzureAd branch, on the OIDC OnTokenValidated event ServiceRegistrationExtensions.cs:137-164. appsettings.json ships AzureAd:ClientId as an empty string appsettings.json:40, so without Key Vault the branch is skipped and no UserSignedIn record is ever written. Guest and ANON sign-ins never emit one in any configuration. The class documents a sampling guarantee — “Each app’s telemetry registration keeps sign-in records out of the sampled set” SignInTelemetry.cs:31 — that this app does not implement; its sampler is an unconditional 10 % ratio ServiceRegistrationExtensions.cs:65.

AI interception is bypassed on the directorMedium

AiInterception.BuildClientOptions exists so Test-environment AI calls are answered locally “without spending a single token” AiInterceptionHandler.cs:1-3. The vision service passes it AiFoundryVisionService.cs:56; the director does not construct its client with options at all AiFoundryDirectorService.cs:49-51. Interception therefore covers vision only. The integration suite is unaffected because it substitutes MockDirectorService over the registration ProcessingEndpointsTests.cs:111 — but a Test-environment run that does not perform that substitution will call the live deployment.

Inconsistent between client and API

The retry button sends a query parameter nothing bindsMedium

“Retry with Safe Fallback Mode” posts to /api/processing/sessions/{id}/initiate?forceFallback=true Engine.razor:88. The handler’s signature is (SessionId, IVideoSessionRepository, IEngineRunDispatcher, HttpContext, CancellationToken) ProcessingEndpoints.cs:13-18 — there is no forceFallback parameter and no read of Request.Query. The retry is identical to a normal initiate; the label promises a mode that does not exist.

The History page re-hides the failed sessions the repository deliberately surfacesMedium

ListCompletedAsync returns Complete and Error rows on purpose: “Failed sessions are intentionally surfaced so the user can find and retry them from the History page rather than re-running from scratch” IRepositories.cs:21-25VideoSessionTableRepository.cs:73-76. The History page then requests /api/ingestion/sessions?status=Complete Results.razor:205, and the endpoint filters the Error rows back out IngestionEndpoints.cs:192-196. The retry path the repository change was made for is unreachable from the UI.

A dead login path is reachable whenever Entra ID is configuredHigh

options.LoginPath = "/login" is set only in the else branch taken when AzureAd:ClientId is absent ServiceRegistrationExtensions.cs:168-170. When Entra ID is configured, AddMicrosoftIdentityWebApp registers its own cookie scheme and no LoginPath is applied, so the handler keeps the framework default. Observed against the built app under ASPNETCORE_ENVIRONMENT=Staging: GET /api/ingestion/sessions returned 302 Found with Location: /Account/Login?ReturnUrl=%2Fapi%2Fingestion%2Fsessions, and /Account/Login answered 404. The full sequence, and the other two auth findings, are in the Auth & Security report.

A blank KeyVault:Uri silently binds a non-Development host to the shared vaultMedium

Outside Development, an empty or missing KeyVault:Uri is replaced by the hard-coded shared vault URI StartupConfigurationExtensions.cs:21-28PoMemeVideoNaming.cs:8. Key Vault is added after the environment-variable provider, so vault secrets win over environment overrides. Observed: a Staging run started with explicit ConnectionStrings__* environment variables pointing at local Azurite connected to the production storage account instead — /api/memelibrary/sounds returned 206 catalogue rows with stpomemevideo.blob.core.windows.net URLs. Anyone running a non-Development profile locally is pointed at shared infrastructure by default.
