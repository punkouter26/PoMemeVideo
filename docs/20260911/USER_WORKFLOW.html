Tier 3 · Schemas and the validation pipeline

Request and response schemas

The validation pipeline — what there is of one

There is no validation framework in this solution: no FluentValidation, no [ApiController] model-state pipeline, no AddValidation(), no IValidatableObject, and no data-annotation attribute on any request record. Validation happens in exactly four places, in this order.

  1. Route-constraint binding. {sessionId:guid} plus IParsable<SessionId>. A malformed GUID never reaches a handler — the route simply does not match, and the request falls through to the SPA shell. IngestionEndpoints.cs:108StronglyTypedIds.cs:25-30
  2. JSON body binding. A malformed body is answered by the framework with a 400 and, as observed under Staging, Content-Length: 0 — no body at all. GlobalExceptionHandler maps BadHttpRequestException to its own status when it does surface. GlobalExceptionHandler.cs:29-31
  3. Command-level rules. Only IngestVideoCommand has them, thrown as a typed VideoIngestionValidationException carrying an ErrorCode and caught by two exception filters on the endpoint. IngestVideoCommand.cs:63-82IngestionEndpoints.cs:29-47
  4. Ownership resolution. Every session-scoped handler loads by (SessionId, UserId) and returns 404 on null. This is authorization implemented as a lookup, and it is the most consistently applied rule in the codebase. VideoSessionTableRepository.cs:58-68

All three media routes go through BlobStorageService.StreamBlobAsync, which uses OpenReadAsync rather than DownloadStreamingAsync for a reason worth preserving: without a known length “Kestrel serves the response with Transfer-Encoding: chunked and no Content-Length… the browser stops fetching after ~2 seconds of video, the audio track never decodes, and the user sees video but hears silence” BlobStorageService.cs:21-28.

GET /api/memelibrary/sounds/{soundId:guid}/stream — anonymous

Two-stage: serve the local blob if it exists, otherwise, if BlobUrl parses as an absolute http(s) URI, proxy it with a 20-second timeout and a spoofed user agent MemeLibraryEndpoints.cs:187-215. The fallback exists because “the seed metadata references myinstants.com URLs, and until they finish downloading we still want audition to work end-to-end” MemeLibraryEndpoints.cs:148-151. The URL proxied is a value from the SoundAssets table, which the anonymous seed endpoint and the authenticated upload endpoint both write — so an attacker who can write a row can make the server issue an outbound GET to a URL of their choosing.
